## Infrastructure

### Base URLs and env var names
- `getBackendBaseUrl()` = first non-blank of `REACT_PUBLIC_API_URL`, else `""` (`legacy:src/lib/env.ts:3-11,16-17`). `getDirectusBaseUrl()` reads `REACT_APP_BASE_URL` (`legacy:src/lib/env.ts:13-14`). Vite exposes both prefixes to the browser: `envPrefix: ["VITE_", "REACT_"]` (`legacy:vite.config.ts:7`).
- Superset: `VITE_SUPERSET_DOMAIN` (embed SDK `supersetDomain`) (`legacy:src/lib/superset.ts:12,44`). Dashboard IDs: `VITE_SUPERSET_DASHBOARD_ID_1`, `_2`, `_3` (`legacy:src/pages/Charts.tsx:16,21,26`); tabs whose var is unset are dropped (`legacy:src/pages/Charts.tsx:28`). These must match the backend allowlist `SUPERSET_DASHBOARD_IDS` (`backend:.env.example:38-39`).
- Pre-patch only (removed by the patch, see below): `VITE_SUPERSET_USERNAME`, `VITE_SUPERSET_PASSWORD` (git diff of `legacy:src/lib/superset.ts`, old lines 14-15). No remaining reference anywhere in `legacy:src` (grep `VITE_SUPERSET`).
- AI agent: `AGENT_BASE_URL = getBackendBaseUrl() || <hardcoded production DQA host>` (`legacy:src/lib/ai-service.ts:10-12`).
- PeerJS: no host/port/path/key/iceServers configured; `new Peer(userId, { debug: 2 })` (`legacy:src/hooks/useWebRTC.ts:37-39`), so the library defaults apply (public PeerJS cloud signalling broker and the library's default STUN/TURN list, `peerjs ^1.5.5` per `legacy:package.json:68`). `node_modules` is not installed, so the exact defaults were not verified locally. No PeerJS server exists in the backend (grep `peerjs|ExpressPeerServer|stun:|turn:` in backend: no hits).
- Map tiles: hardcoded in `TILE_LAYERS` (`legacy:src/pages/CaseworkerJourneys.tsx:50-72`), no env var.

### Auth / token injection
- `getStoredToken()` reads `localStorage["ecap.access_token"]` once and caches it in a module variable (`legacy:src/lib/auth.ts:1,7,9-23`).
- Superset guest token: always sends `Authorization: Bearer <token>`; throws `"Not authenticated."` before any request if there is no token (`legacy:src/lib/superset.ts:25-33`).
- Agent chat (patched): `agentHeaders()` adds `Authorization: Bearer <token>` only when a token exists; otherwise sends no auth header (`legacy:src/lib/ai-service.ts:14-20,99,156`). Pre-patch it sent only `Content-Type` (git diff, old `headers: { "Content-Type": "application/json" }`), i.e. the assistant only worked with backend `AUTH_MODE=log`.
- PeerJS: no auth at all; the peer ID is the Directus user id (`legacy:src/hooks/useWebRTC.ts:37`, caller `legacy:src/pages/SupportCenter.tsx:298` passes `user?.id`).
- Tiles, Google Fonts, images: anonymous GETs.

### Timeouts, retries, error normalisation, 401 handling, logging
- No call in scope uses `core`-style clients; all use raw `fetch` (`legacy:src/lib/superset.ts:28`, `legacy:src/lib/ai-service.ts:97,154`). No `AbortController`/timeout anywhere (backend agent upstream can take up to 90 s — AUDIT §3.2 `POST /agent/chat`), no retry, no 401 → logout/refresh handling.
- Superset: `response.json().catch(() => null)`; error = `data?.message ?? "Guest token request failed (<status>)"`; success requires `data.token` (`legacy:src/lib/superset.ts:37-41`). This matches the backend `{status,message}` envelope.
- Agent `getAiResponse`: on non-OK reads `errorData.error?.message` else `"Agent request failed: <status> <statusText>"` (`legacy:src/lib/ai-service.ts:107-113`); logs `console.error("Bumi AI error:")` and rethrows (`:117-120`). `getAiGreeting`: on non-OK throws the fixed string `"Greeting fetch failed"` (`:170`), no logging.
- EmbeddedDashboard: catches any embed error, `console.error`, shows message + Retry button which re-runs `embed` (`legacy:src/components/dashboard/EmbeddedDashboard.tsx:56-62,128`).
- PeerJS: `debug: 2` (warnings + errors from the library) plus many `console.log`/`console.error` lines, two of them printing peer IDs (`legacy:src/hooks/useWebRTC.ts:38,42,46,52,58,63,69,97,103,108,113,131,135,181,206`).

### Client-side caches
- Guest token: **none client-side**. `fetchGuestToken` is called by the embedded SDK through the callback (`legacy:src/components/dashboard/EmbeddedDashboard.tsx:40-45`); any refresh-before-expiry is SDK-internal (`@superset-ui/embedded-sdk ^0.3.0`, `legacy:package.json:47`; not verifiable without node_modules). Backend does not cache guest tokens either (AUDIT §3.2 `POST /superset/guest-token`).
- AI chat history: `localStorage["ecap.chat_history.<userId>"]` (or `.guest`), loaded on key change and rewritten on every message change (`legacy:src/components/dashboard/AiAssistant.tsx:118,125-142`); cleared by `clearChat` (`:120-123`). Open/closed state: `localStorage["ai_assistant_open"]` (`:37-42`). Greeting snapshot: `localStorage["bumi.snapshot.<userId|email|guest>"] = {ts}` (`:157,160-179`).
- No request de-duplication in any call in scope (guest token, agent chat). The greeting is guarded only by a `greetedRef` per mount (`legacy:src/components/dashboard/AiAssistant.tsx:149-156`), and `AiAssistant` is rendered by `DashboardLayout` (`legacy:src/components/dashboard/DashboardLayout.tsx:23,52`), which each page renders itself (40 files under `legacy:src/pages` import it, e.g. `legacy:src/pages/Charts.tsx:2,37`), so the assistant remounts on every route change (see Issue 23).

### Security-fix patch (git diff) in scope
- `legacy:src/lib/superset.ts` — **before**: browser logged in to Superset `POST {VITE_SUPERSET_DOMAIN}/api/v1/security/login` with `{username: VITE_SUPERSET_USERNAME, password: VITE_SUPERSET_PASSWORD, provider:"db", refresh:true}`, then `POST {VITE_SUPERSET_DOMAIN}/api/v1/security/guest_token/` with `Bearer <access_token>` and body `{user, resources:[{type:"dashboard", id}], rls}`; `rls` defaulted to `[]` and no caller ever passed it, so **no RLS was applied for anyone**; `user` came from the caller (email/first/last name, `legacy:src/components/dashboard/EmbeddedDashboard.tsx:41-45`) or `{guest, Guest, User}`. Login was repeated on every guest-token request (no access-token cache). No `/csrf_token` call existed client-side. **After**: one `POST {REACT_PUBLIC_API_URL}/superset/guest-token` with `Bearer <Directus token>` and body `{dashboardId}`; the `_user` argument is accepted but ignored (`legacy:src/lib/superset.ts:21-35`). Service-account login, optional CSRF and guest-token calls plus RLS now live in the backend (AUDIT §3.2 `POST /superset/guest-token`). **No RLS clause is built client-side any more.**
- `legacy:src/lib/ai-service.ts` — only added `agentHeaders()` (Bearer token when present) to both `/agent/chat` calls (`:8,14-20,99,156`). The hardcoded fallback host (`:10-12`) was not removed.

### AI assistant specifics
- **Request shape:** OpenAI-style `{messages:[{role, content}], temperature, max_tokens}` (`legacy:src/lib/ai-service.ts:100-104,157-167`). No `model` field sent (backend default applies). No `stream` field; backend forces `stream:false` — **not streaming**.
- **Response shape read:** `choices[0].message.content` only (`legacy:src/lib/ai-service.ts:116,172`).
- **System prompts (do not port text):** chat prompt constant `SYSTEM_PROMPT` at `legacy:src/lib/ai-service.ts:27-82`; page-context system message at `:85-88`; greeting prompt at `:140-152`. All three are client-supplied, so the backend's default prompt is never used (AUDIT §3.2).
- **Conversation history:** the full in-memory/localStorage history is resent on every turn (`legacy:src/components/dashboard/AiAssistant.tsx:79`), unbounded, including the auto greeting and the stored assistant replies (`:104-105`). A JSON command block is stripped from the stored reply only when it is a valid allowlisted `change_color` command (`:85-95`); a block with another `action` is replaced by a fixed refusal string (`:96-97`); an unparsable block or a `change_color` with a non-allowlisted target is stored and resent verbatim (`:88,99-101`). Error placeholders ("connection issue") are also stored and resent (`:107-112`).
- **Client-side command execution:** the first ```` ```json ```` block with `action:"change_color"` and `target` in an allowlist calls `updateColor(target, value)` (`legacy:src/components/dashboard/AiAssistant.tsx:51-53,83-90`); `value` is not validated client-side.
- **Context sent:** `currentPage` = `document.title.split("-")[0].trim() || "Dashboard"` (`legacy:src/components/dashboard/AiAssistant.tsx:78`); greeting sends first name, role name (`role.name`, a role string, or `"user"`), away duration and `location.pathname` (`:157-159,168-178,182-189`).

## Issues

1. **`currentPage` context is always "PMP".** It is derived from `document.title` (`legacy:src/components/dashboard/AiAssistant.tsx:78`), but nothing in `legacy:src` ever sets the title (grep `document.title`/`Helmet`/`<title`: only this read), so it is always the static `<title>` from `legacy:index.html:16`. The page-context system message (`legacy:src/lib/ai-service.ts:85-88`) is therefore useless.
2. **`max_tokens: 1024` is silently capped to 600 by the backend** (`legacy:src/lib/ai-service.ts:103` vs AUDIT §3.2 `POST /agent/chat`). Long answers are truncated (`finish_reason:"length"`) with no UI signal.
3. **Unbounded history resend.** Every turn posts the whole stored history plus a ~55-line system prompt (`legacy:src/components/dashboard/AiAssistant.tsx:79`, `legacy:src/lib/ai-service.ts:90-94`). Backend body cap is `express.json()` default 100 kB (AUDIT §3.2); past it the backend returns an **HTML 413**, which `getAiResponse` cannot parse (`.json().catch(()=>({}))`, `:108`) → generic error forever, until the user clears chat. No truncation/windowing.
4. **Error-envelope mismatch for the agent.** `getAiResponse` only reads `error.message` (`legacy:src/lib/ai-service.ts:110`); backend auth failures use `{status,message}` (AUDIT §3.2 notes), so a 401 shows the generic status text. The UI hides all of it behind one fixed string anyway (`legacy:src/components/dashboard/AiAssistant.tsx:107-112`). No 401 → re-login handling anywhere in scope.
5. **No timeout on agent calls.** Backend may hold a request up to 90 s (AUDIT §3.2); the frontend `fetch` has no `AbortController` (`legacy:src/lib/ai-service.ts:97,154`), and sending is blocked while `isLoading` (`legacy:src/components/dashboard/AiAssistant.tsx:70`; input and send button `disabled`, `:354,360`).
6. **Hardcoded fallback host.** `AGENT_BASE_URL` falls back to the hardcoded production DQA host when `REACT_PUBLIC_API_URL` is empty (`legacy:src/lib/ai-service.ts:10-12`); the patch did not remove it. Inconsistent with `fetchGuestToken`, which has no fallback (`legacy:src/lib/superset.ts:28`): with an empty env var it posts to a relative `/superset/guest-token` on the SPA origin; whatever non-JSON response the static host returns makes `data` `null`, so it throws `"Guest token request failed (<status>)"` (`:37-39`).
7. **Hardcoded hosts in `index.html`.** Preconnects to the production DQA and Directus hosts (`legacy:index.html:11-14`) and brand strings in meta tags (`:16-21`); `allowedHosts` hardcodes production/staging hostnames (`legacy:vite.config.ts:22,27`). In the rebuild these must come from config/env.
8. **`envPrefix: ["VITE_", "REACT_"]`** (`legacy:vite.config.ts:7`) ships every `REACT_*` env var to the browser, widening the "no secrets in client env" surface beyond `VITE_*`. Pre-patch, `VITE_SUPERSET_USERNAME/PASSWORD` were shipped in the bundle (git diff); any already-built/deployed bundle still contains them → the Superset service-account password must be treated as leaked and rotated (Backend ask).
9. **Pre-patch Superset had no RLS at all** (`rls` defaulted to `[]` and was never passed — git diff; `legacy:src/components/dashboard/EmbeddedDashboard.tsx:41-45` passes only a user). Every embedded-dashboard viewer saw national data. Now enforced server-side (AUDIT §3.2), with the scope-heuristic caveats noted there.
10. **Stale `user` argument and needless re-embeds.** `EmbeddedDashboard` still builds a user object from the email/name and passes it to `fetchGuestToken`, which ignores it (`legacy:src/components/dashboard/EmbeddedDashboard.tsx:41-45`, `legacy:src/lib/superset.ts:23`). `user` is still a `useCallback` dependency (`:63`), so any change in the `user` object identity re-runs `embedDashboard` and reloads the iframe. The SDK's returned `unmount` handle is never called (`:36`).
11. **Dashboard-ID parity is manual.** `VITE_SUPERSET_DASHBOARD_ID_1..3` (`legacy:src/pages/Charts.tsx:16-26`) must match backend `SUPERSET_DASHBOARD_IDS` (`backend:.env.example:38-39`); a mismatch yields a 400 "Unknown or non-embeddable dashboard." shown in the error overlay. Tab labels are hardcoded with brand text (`legacy:src/pages/Charts.tsx:15`), and the empty-state copy tells end users to edit env vars and restart the dev server (`legacy:src/pages/Charts.tsx:107-110`).
12. **`/charts` has no permission or feature flag** — only `ProtectedRoute` (`legacy:src/App.tsx:406-410`); data restriction relies entirely on backend RLS.
13. **PeerJS uses a public third-party broker with user IDs as peer IDs** (`legacy:src/hooks/useWebRTC.ts:37-39`). No auth: anyone who knows (or guesses) a Directus user id can register that peer ID first (hijacking incoming calls) or ring that user; call metadata transits a third-party service; TURN relay (if used) is the library's public default. No backend route or self-hosted PeerServer exists. Security / data-residency concern; the rebuild needs a self-hosted signalling + TURN config from env, or the feature dropped.
14. **WebRTC cleanup bug — camera/mic left on.** The `peer.on("call")` handler is registered once per `userId` (`legacy:src/hooks/useWebRTC.ts:34-77`) and captures the first-render `cleanup`, whose `localStream` is `null` (`:17-31`).
