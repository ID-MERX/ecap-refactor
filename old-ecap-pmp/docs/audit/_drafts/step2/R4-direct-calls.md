# Step 2 draft R4: direct calls and call sites in pages/components

Scope: the network-call aspects of 25 files (3 components in `components/chat` + `components/dashboard`, `EtlInvalidator`, `useCalendarNotifications`, and 18 pages). The DQA and Directus wrappers in `src/lib/api.ts` / `src/lib/directus.ts` are listed here only as callers (with a short target note so the table stands alone). Calls that bypass those wrappers are documented in full.

No file in scope uses axios, the Directus SDK, `window.open` or `XMLHttpRequest` (grep of all 25 files). The only raw `fetch` calls in scope are in `legacy:src/components/EtlInvalidator.tsx:35`, `legacy:src/pages/ForgotPassword.tsx:32` and `legacy:src/pages/ResetPassword.tsx:41`. The only `EventSource` is in `legacy:src/pages/DataPipelinePage.tsx:295`. Hand-built browser-native URLs are the ETL CSV anchor download (`legacy:src/pages/DataPipelinePage.tsx:392-399`) and Directus asset URLs from `getFileUrl` (`<img src>`, `<audio src>` and `<a href download>`).

Files in scope that make **no network call of their own**: `legacy:src/pages/TrainingLog.tsx` (its `getTrainingLog` is a mock: `legacy:src/constants/api.ts:8,25-29` returns `generateMockTrainingLog()` after a 300 ms delay); `legacy:src/components/chat/CallOverlay.tsx` and `legacy:src/components/dashboard/AppSidebar.tsx` only build avatar URLs with `getFileUrl` (`:62`, `:306`). `legacy:src/components/chat/ProfilePictureModal.tsx:5` imports `getFileUrl` but never calls it (it receives `currentAvatarUrl` already built by `legacy:src/pages/SupportCenter.tsx:833-837`).

## Infrastructure

### Base URLs (env var names)
- `legacy:src/lib/env.ts:13-14` `getDirectusBaseUrl()` reads `REACT_APP_BASE_URL`; `legacy:src/lib/env.ts:16-17` `getBackendBaseUrl()` reads `REACT_PUBLIC_API_URL`. Both return `""` when unset (`:3-11`). These non-`VITE_` names are exposed to the browser because `envPrefix: ["VITE_", "REACT_"]` (`legacy:vite.config.ts:7`).
- `legacy:src/lib/directus.ts:5-11` `requireDirectusUrl()` throws `"REACT_APP_BASE_URL is not set"`. The direct `fetch` calls in `ForgotPassword`/`ResetPassword` do **not** use it, so with the variable unset they post to a relative path `/auth/password/...` on the SPA origin (`legacy:src/pages/ForgotPassword.tsx:30-32`, `legacy:src/pages/ResetPassword.tsx:41`). The three flag wrappers in `api.ts` do the same (`getDirectusBaseUrl()` with no guard, `legacy:src/lib/api.ts:615,635,1288`). Neither raw page fetch strips a trailing slash from the base, unlike `directusRequest`/`requestPasswordReset` (`legacy:src/lib/directus.ts:26,269`).
- `EtlInvalidator` captures the DQA base URL once at module load (`legacy:src/components/EtlInvalidator.tsx:29`), the same way `api.ts` does (`legacy:src/lib/api.ts:5`).
- Other env names read by in-scope code: `VITE_RESET_PASSWORD_URL` (reset-link base, falls back to `window.location.origin`: `legacy:src/pages/ForgotPassword.tsx:28`, `legacy:src/pages/AddUser.tsx:407`, `legacy:src/pages/Users.tsx:123-125`, `legacy:src/pages/Profile.tsx:233`); `VITE_DIRECTUS_USER_ROLE` (role id used as a filter by `listUserActivity`/`listPmpUsers`, `legacy:src/lib/directus.ts:791,829`, and read but unused in `listUsers`, `legacy:src/lib/directus.ts:3,85-95`); `VITE_DEFAULT_DISTRICT` (`legacy:src/lib/api.ts:7`, imported but never used by `legacy:src/pages/HouseholdProfile.tsx:6`, `legacy:src/pages/VcaProfile.tsx:6`, `legacy:src/pages/HouseholdServicesPage.tsx:38`); `VITE_DEBUG_API` (`legacy:src/lib/api.ts:15-16`).

### Token injection
- Token source: `getStoredToken()` reads `localStorage["ecap.access_token"]` once and memoises it in a module variable (`legacy:src/lib/auth.ts:1,9-23`); `setStoredToken`/clear update the memo (`:30-31,39-40`).
- Directus wrapper: `directusRequest` throws `"Not authenticated."` without a token, sets `Authorization: Bearer`, merges caller headers, and sets `Content-Type: application/json` unless the body is `FormData` (`legacy:src/lib/directus.ts:21-57`).
- DQA wrappers: `dqaGet` (`legacy:src/lib/api.ts:185-210`), `dqaPost` (`:683-699`), `dqaGetSkipCache` (`:701-712`) all set `Authorization: Bearer`.
- Raw `fetch` in `EtlInvalidator` adds `Authorization: Bearer` and returns `null` with no token (`legacy:src/components/EtlInvalidator.tsx:33-40`). This header was **added by the uncommitted security-fix patch** (`git diff`: previously only `Content-Type: application/json`, so in `AUTH_MODE=enforce` every poll got 401, returned `null`, and cache invalidation never fired).
- **Token in the query string:**
  - `?token=` for DQA browser-native requests via `withTokenParam` (`legacy:src/lib/api.ts:751-757`), used by `getEtlDownloadUrl` (`:759-766`) and `getTabletSyncStreamUrl` (`:796-798`). **Added by the security-fix patch** (before it, both URLs carried no token and failed with 401 under enforce mode). The backend accepts this fallback (§3.1 item 2, `backend:middleware/verifyDirectusToken.js:31-40`).
  - `?access_token=` for Directus assets via `getFileUrl` (`legacy:src/lib/directus.ts:215-221`): token appended raw (not `encodeURIComponent`), used for every avatar `<img>` and every chat attachment `<img>`/`<audio>`/`<a href download>` (`legacy:src/pages/SupportCenter.tsx:376-420`).
- Public (no-token) calls: `ForgotPassword` and `ResetPassword` raw fetches; `requestPasswordReset` (`legacy:src/lib/directus.ts:268-286`); `acceptUserInvite` via `publicBackendRequest` (`legacy:src/lib/directus.ts:288-308`).

### Timeouts, retries, de-duplication
- No `AbortController`/timeout anywhere in the in-scope paths or the wrappers they call (grep of `legacy:src/lib/api.ts`, `legacy:src/lib/directus.ts` and the 25 files).
- Retries come only from React Query: the app-wide default is `retry: 1` (`legacy:src/App.tsx:131`); per-query overrides are `retry: false` for `EtlInvalidator` (`legacy:src/components/EtlInvalidator.tsx:60`) and VCA services (`legacy:src/pages/VcaServicesDashboard.tsx:287`); `retry: 1` for household services (`legacy:src/pages/HouseholdServicesPage.tsx:75`).
- De-duplication is only React Query's per-key de-dup. Several pages use **different keys for the same request** so it is fetched twice: `getChildrenByDistrict("", fyArg)` under `["vca-districts-discovery", fyKey]` and `["vca-vcas-all","All",fyKey]` (`legacy:src/pages/VcaServicesDashboard.tsx:248-252,275-279`); the calendar under `["calendar-events", id]` (`legacy:src/pages/Calendar.tsx:106-110`, `legacy:src/hooks/useCalendarNotifications.ts:12-17`) and `["calendar-events-widget", id]` (`legacy:src/components/dashboard/CalendarWidget.tsx:16-20`); the national household register `getHouseholdsByDistrict("")` under `["districts-discovery","All"]` (`legacy:src/pages/AddUser.tsx:178-182`, `legacy:src/pages/EditUser.tsx:61-65`), `["hh-districts-discovery-services", fyKey]` (`legacy:src/pages/HouseholdServicesPage.tsx:52-56`, identical request when no FY window is set) and `["households","district",""]` (`legacy:src/pages/HouseholdProfile.tsx:154-158`); `getFlaggedRecords` under `["flagged-records"]` (Flags, profiles) and `["recent-flags"]` (`legacy:src/components/dashboard/RecentActivity.tsx:98-101`). The IndexedDB layer (below) partly hides the duplicate DQA fetches (not the flag fetches, which bypass it).

### Error normalisation
- Directus wrapper: non-2xx throws `Error(errors[0].message ?? "Directus request failed")` (`legacy:src/lib/directus.ts:51-54`).
- DQA wrappers: `Error(data.message ?? "DQA request failed")` (`legacy:src/lib/api.ts:205-207`) or `"Request failed: <status>"` (`:696-697,709-710`).
- Flag wrappers in `api.ts` talk to Directus but read the DQA-style `message` key (`legacy:src/lib/api.ts:646-649,1299-1302`), so Directus' `errors[0].message` is never shown.
- `getFlaggedRecords` never checks `response.ok` and swallows all errors to `[]` (`legacy:src/lib/api.ts:604-628`).
- `publicBackendRequest` never checks `response.ok` and returns nothing (`legacy:src/lib/directus.ts:288-301`); it throws only on a network failure or an unset `REACT_APP_BASE_URL` (`:292`).
- Raw fetches: `EtlInvalidator` maps every failure to `null` (`legacy:src/components/EtlInvalidator.tsx:41-46`); `ResetPassword` throws `errors[0].message ?? "Reset failed"` (`legacy:src/pages/ResetPassword.tsx:49-52`); `ForgotPassword` surfaces the Directus error only in DEV and shows the generic success text in production even on failure (anti-enumeration, `legacy:src/pages/ForgotPassword.tsx:40-61`).

### 401 / expiry handling
- None. No wrapper inspects 401; an expired token just becomes a thrown error message (Directus: "Token expired." style message from `errors[0]`; DQA: §3.1 401 reasons) shown in a toast or swallowed. grep for `refresh|401|expire` in `legacy:src/lib/auth.ts` and `legacy:src/context/AuthContext.tsx` finds only `refreshProfile` (`legacy:src/context/AuthContext.tsx:31,76,160`), which reloads the profile and does not refresh the token.
- `EtlInvalidator` treats 401 as "no new run" (`legacy:src/components/EtlInvalidator.tsx:41`), so an expired session silently stops cache invalidation.
- `EventSource` gets a 401 JSON before the stream opens (§3.2 `/etl/tablet-sync/stream`, Errors); the page only flips the badge to `"reconnecting"` (`legacy:src/pages/DataPipelinePage.tsx:346-348`).

### Debug logging
- `VITE_DEBUG_API === "true"` in DEV logs every DQA URL and response body (`legacy:src/lib/api.ts:15-16,190-203`).
- Unconditional logging of raw records: `VcaServicesDashboard` logs the field names and the first 3 VCA service records **on every render** (`legacy:src/pages/VcaServicesDashboard.tsx:305-308`).
- `EtlInvalidator` logs each invalidation with `console.info` (`legacy:src/components/EtlInvalidator.tsx:81-83`). `ForgotPassword` logs the Directus error body with `console.error` in all builds (`legacy:src/pages/ForgotPassword.tsx:42`).

### Client-side caches
- **IndexedDB** `ecap_plus_cache_db` / store `api_cache`, version 1 (`legacy:src/lib/indexedDbCache.ts:6-8`), used by `getListFromApiWithCache` (`legacy:src/lib/api.ts:211-237`): serve the entry if younger than the TTL, otherwise fetch; on fetch error, **serve a stale entry of any age** with a `console.warn`. TTLs: `LIST_CACHE_TTL_MS` 60 s for registers (`:14`), `SERVICES_CACHE_TTL_MS` 5 min for service lists (`:8`). Cache keys normalise `""` to `"ALL"` and append `:<from>_<to>` when an FY window is sent (`:303-310,372-380`). The IDB cache is not keyed by user, so it survives logout and is shared between accounts on the same browser profile (keys contain no user id; `legacy:src/lib/api.ts:306-308`).
- **React Query persistence** (separate from the store above): every successful query is persisted to IndexedDB through `idb-keyval` under key `ecap-plus-pmp-react-query` for 24 h (`legacy:src/App.tsx:140-148,214-224`, `shouldDehydrateQuery` keeps every `success` query). In scope this includes chat messages, the chat user list (emails, roles, locations), bell notifications, calendar events and the whole flag list. Logout only clears the token (`legacy:src/context/AuthContext.tsx:148-151`), so neither IDB cache is cleared on logout.
- `EtlInvalidator` wipes the whole IDB store (`clearAllCacheEntries`) and invalidates every React Query key except those starting with `"etl"` when `last_success_at` moves forward (`legacy:src/components/EtlInvalidator.tsx:63-85`). The first poll only sets the baseline (`:68-71`). Comparison is a string `>` on ISO timestamps (`:73`).
- **localStorage** stat snapshots: `ecap_cache_nationwide_household_list` read (`legacy:src/pages/HouseholdServicesPage.tsx:79-87`) and written when `selectedDistrict === "All"` (`:119-122`); `ecap_cache_nationwide_vca` read (`legacy:src/pages/VcaServicesDashboard.tsx:290-298`) but **never written** anywhere (grep `setItem` in that file: none).
- **sessionStorage** holds the profile page record id (`ecap_last_household_id`, `legacy:src/pages/HouseholdProfile.tsx:140-147`; `ecap_last_vca_id`, `legacy:src/pages/VcaProfile.tsx:189-196`). Not a network cache, but it decides which by-ID endpoints are called.

## Issues

1. **`acceptUserInvite` cannot fail and probably targets the wrong path.** It posts to `${REACT_APP_BASE_URL}/directus/users/invite/accept` (`legacy:src/lib/directus.ts:303-307`). Standard Directus serves `/users/invite/accept` at the base, so the extra `/directus` segment only works if the base URL points at a proxy that strips it. `publicBackendRequest` never checks `response.ok` or reads the body (`:288-301`), so `AcceptInvite` shows "Invitation accepted" for any HTTP response (`legacy:src/pages/AcceptInvite.tsx:49-53`). In addition `AddUser` never sends invites (`activationMode` is fixed to `"invite"`, which means password-reset mail, `legacy:src/pages/AddUser.tsx:173,320-322`) and `inviteUser` is unused, so this page is reachable only through old invite links.
2. **`HouseholdServicesPage` "All" returns nothing.** It sends `"*"` for "All" (`legacy:src/pages/HouseholdServicesPage.tsx:71`); the backend treats only `"All"`/`""` as "no filter" and otherwise does `ah.district IN ('*')` (`backend:controllers/householdController.js:379-386`), so the nationwide view gets `[]`. The page then shows the localStorage snapshot `ecap_cache_nationwide_household_list` (`:119-128`), which is only written when the result is non-empty, so it is stale or absent.
3. **Errors parsed as data in `getFlaggedRecords`.** `response.ok` is never checked (`legacy:src/lib/api.ts:614-623`). A Directus 401/403 body `{errors:[…]}` is passed to `getListValue`, whose step 3 returns the first non-empty array of any key (`legacy:src/lib/api.ts:166-172`), so the `errors` array becomes the "flag list". No `limit` is sent, so Directus' default page size applies and later flags are silently missing. No filter: every user downloads every flag and pages filter client-side; the `Flags` geo filter uses `district`/`province` fields that no in-scope create call writes (`legacy:src/pages/Flags.tsx:53-63`).
4. **Directus error messages lost in the flag wrappers.** `createFlaggedRecord`/`updateFlagStatus` read `errorData.message` (`legacy:src/lib/api.ts:646-649,1299-1302`) but Directus returns `errors[0].message` (which `directusRequest` reads correctly, `legacy:src/lib/directus.ts:51-54`). Two different Directus clients with different error parsing: duplicated infrastructure (the flag wrappers are raw `fetch` in `api.ts`, outside `directusRequest`).
5. **Resolving a flag can report failure after it succeeded.** `updateFlagStatus` runs first, then `notifyUsersOfFlagResolution` is awaited (`legacy:src/pages/Flags.tsx:172-176`, `legacy:src/pages/HouseholdProfile.tsx:301-315`, `legacy:src/pages/VcaProfile.tsx:327-341`). The notifier first lists **all active users** (`legacy:src/lib/directus.ts:690`); a user without read access to `directus_users` gets a throw, and the mutation shows "Failed to resolve flag" although the status was already changed. Creation calls the same notifier fire-and-forget (unhandled promise rejection; `legacy:src/pages/FlaggedRecordForm.tsx:75`, `legacy:src/pages/HouseholdProfile.tsx:282`, `legacy:src/pages/VcaProfile.tsx:364`). Recipient selection is by role-name substring (`legacy:src/lib/directus.ts:638-655`), the kind of string comparison the new app forbids, and it fans out N `POST /notifications` from the browser.
6. **Inconsistent flag payloads.** `FlaggedRecordForm` sends no `category`/`severity` and defaults to `"Not Available"`; the profile pages send both and default to `"N/A"` (`legacy:src/pages/FlaggedRecordForm.tsx:50-57,94-104` vs `legacy:src/pages/HouseholdProfile.tsx:335-347`, `legacy:src/pages/VcaProfile.tsx:387-399`). `notifyUsersOfFlag` special-cases only an empty value and `"Not Available"` (`legacy:src/lib/directus.ts:665-668`), so the `"N/A"` placeholders leak into the text: VcaProfile passes `id || "N/A"` as the VCA and `household_id || "N/A"` as the household (`legacy:src/pages/VcaProfile.tsx:364-369`), giving "VCA … (HH N/A)" when the register row has no household id. The household profile passes no `vca_id` to either the payload or the notifier (`legacy:src/pages/HouseholdProfile.tsx:282-286,335-347`), so its flags are announced as "Household <id>".
7. **Collection mismatch for flags.** The flag pages read/write `flagged_forms_ecapplus_pmp` (`legacy:src/lib/api.ts:615,634,1288`), but the User Activity tab counts flags from `flagged_forms_ecapii` (`legacy:src/lib/directus.ts:861-870`). `deleteUser` scrubs both (`legacy:src/lib/directus.ts:438-449`).
8. **`deleteUser` destroys business records.** When a hard delete hits an FK error it **deletes** every flagged form that references the user in `user_created/created_by/flagged_by/caseworker` and every calendar event that references them in `user_id/user_created/created_by` (fallback: nulls the field), and deletes all their sent and received notifications, all from the browser, 200 rows per field at most, ignoring every error (`legacy:src/lib/directus.ts:371-404,406-424,437-454`). This should be a backend/Directus-flow concern (Backend ask).
9. **`AddUser` silently overwrites existing accounts.** It looks the email up and, if found, `PATCH`es that user with the new role, scope, `status:"active"` and `password_change_required:false` (`legacy:src/pages/AddUser.tsx:307-318`). A user in the trash (suspended) is reactivated with no warning. The reset URL is also not trailing-slash-trimmed, unlike the three other call sites (`legacy:src/pages/AddUser.tsx:407-411` vs `legacy:src/pages/Users.tsx:123-126`, `legacy:src/pages/Profile.tsx:233-234`, `legacy:src/pages/ForgotPassword.tsx:28-29`).
10. **Duplicate password-reset request code.** `ForgotPassword` hand-builds the same `POST /auth/password/request` that `requestPasswordReset` already wraps (`legacy:src/pages/ForgotPassword.tsx:32-38` vs `legacy:src/lib/directus.ts:268-285`), with different behaviour (lower-casing, prod error swallowing). `ResetPassword` has no wrapper at all (`legacy:src/pages/ResetPassword.tsx:41-47`). Both use `getDirectusBaseUrl()` without `requireDirectusUrl()`, so an unset `REACT_APP_BASE_URL` posts to the SPA origin.
11. **Tokens in URLs.** `getFileUrl` appends the raw Directus access token as `?access_token=` to every avatar/attachment URL (`legacy:src/lib/directus.ts:215-221`), so it lands in the DOM, browser history, proxy logs and any copied image link; it is also not URL-encoded. The security patch added `?token=` to the ETL download and SSE URLs (`legacy:src/lib/api.ts:751-766,796-798`); the download opens in a new tab (`legacy:src/pages/DataPipelinePage.tsx:392-399`), so the token shows in the address bar and history, and the backend 404 catch-all echoes the URL (§3.1 item 2). The SSE URL bakes in the token at connect time; after expiry the 401 makes `EventSource` stop (spec: non-200 fails the connection) and the page stays on "reconnecting" until the tab is switched (`legacy:src/pages/DataPipelinePage.tsx:281-354`).
12. **No session-expiry handling anywhere in scope** (see Infrastructure). `EtlInvalidator` turns 401 into "no change", so an expired session silently disables cache invalidation (`legacy:src/components/EtlInvalidator.tsx:41`).
13. **Over-fetching national data for small lookups.**
    - Profile pages download the whole active register, archived register and VCA register to find one record (`legacy:src/pages/HouseholdProfile.tsx:154-210`, `legacy:src/pages/VcaProfile.tsx:203-213`). §3.2 notes the by-ID VCA endpoint is broken, which may be why.
    - AddUser/EditUser download the national household register only to build province/district/ward pickers (`legacy:src/pages/AddUser.tsx:177-224`, `legacy:src/pages/EditUser.tsx:61-65`).
    - VcaServicesDashboard fetches national VCA services even for district users and filters in the browser (`legacy:src/pages/VcaServicesDashboard.tsx:236-241,282-288,349-363`). This is UX-only scoping; it relies on the backend, which trusts the district param (§3.1 item 3).
    - The district-user rule is a string compare on `description === "District User"`, and the user gets `"None"` as district if `location` is empty (`legacy:src/pages/HouseholdProfile.tsx:150-152`, `legacy:src/pages/VcaProfile.tsx:199-201`).
14. **FY window not applied on detail and service pages.** HouseholdProfile/VcaProfile call the cohort registers with no `from`/`to` (`legacy:src/pages/HouseholdProfile.tsx:156,162,208`, `legacy:src/pages/VcaProfile.tsx:205,211`). HouseholdServicesPage and VcaServicesDashboard put `fyKey` into query keys but never send FY to the services endpoints (`legacy:src/pages/HouseholdServicesPage.tsx:69-71`, `legacy:src/pages/VcaServicesDashboard.tsx:282-285`). The backend ignores FY there anyway (§3.2 FY = none), so the FY selector changes only the cache key (a refetch with identical data).
15. **Chat data model problems.**
    - `getChatMessages` sorts **ascending** with `limit=500` (`legacy:src/lib/directus.ts:119-122`), so once a user has more than 500 messages the newest ones are cut off.
    - It polls every 3 s (`legacy:src/pages/SupportCenter.tsx:63`).
    - The outbox copy is a notification addressed to the sender with no explicit status (`legacy:src/lib/directus.ts:166-173`), while the bell lists every `status=inbox` notification for the user with no collection filter (`:486-497`). So if Directus defaults the status to `inbox` (Directus behaviour, not verified in this repo), senders see their own sent messages in the bell, linked to `/support?userId=<self>` (`legacy:src/components/dashboard/DashboardHeader.tsx:127-131`).
    - The `|||FILE:<id>` suffix encoding is a string protocol inside `message` (`legacy:src/lib/directus.ts:170`), and **nothing ever parses it** (grep of `legacy:src` for `|||` finds only the writer). Attachments render only for `support_chat` inbox copies (`legacy:src/pages/SupportCenter.tsx:376`), so the sender sees their own attachment as plain text with the raw suffix (`:446-448`). The attachment type itself is encoded as an emoji prefix ("🎤", "📷", "📎") in `message` (`:315,326,380,393,405`).
    - `listUsers` returns all users (`limit=-1`) with email, role, location and facility to every chat user, and hides admins and "ECAP II" roles only on the client by role-name comparison (`legacy:src/lib/directus.ts:79-100`, `legacy:src/pages/SupportCenter.tsx:73-107`).
